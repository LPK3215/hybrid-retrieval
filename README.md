# D04 · 混合检索实验台（Hybrid Retrieval Bench）

> 一个可离线复现的 Hybrid Retrieval 实验与演示平台：稠密向量（Chroma）+ 稀疏关键词（rank_bm25/jieba）双路召回，RRF 融合，bge-reranker-base 交叉编码器重排，配 20 条人工标注测试集、五组工程探针与毫秒级时延口径。
> 定位：Agent 专项 D04 模块的落地实现，代码、实验数据与工具形态三者齐备。

## 一、它是什么

把「文档处理与 RAG」专项里关于混合检索的判断做成可跑、可测、可演示的东西：

- **四种检索模式**：`vector`（纯稠密）/ `bm25`（纯稀疏）/ `rrf`（融合）/ `rrf_rerank`（融合 + 重排）
- **20 条标注测试集**：12 条精确词（含专有名词/参数，BM25 强项）+ 8 条语义改写（自然语言转述，向量强项），每条人工核对块全文后绑定 1~3 个 gold 块
- **五项指标**：Recall@3/5/10、MRR、nDCG、时延 p50，按 query 类型分组
- **五组工程探针**：分词方式 / BM25 阈值 / RRF k / 候选数 / 块大小，把「经验口径」变成数字
- **工具形态**：FastAPI 网关 + 单页前端（`localhost:8622`），支持四模式横向对比、gold 高亮与实时指标
- **零外部网络**：全部模型走本地 HuggingFace 缓存（`HF_HUB_OFFLINE=1`），实验可复现

## 三、快速开始

```powershell
# 1. 装依赖（本机已装则跳过）
pip install -r requirements.txt

# 2. 机制自测（10 秒内，不依赖模型精度）
python -m src.cli selftest

# 3. 建索引（切分 + 双索引，约 1 分钟）
python -m src.cli build-index

# 4. 跑四组对照主实验（约 2 分钟）
python -m src.cli bench

# 5. 跑五组工程探针（约 5-8 分钟，块大小探针会重建索引）
python -m src.cli probes

# 6. 启动工具平台（浏览器打开 http://127.0.0.1:8622）
python -m src.cli serve

# 7. 命令行演示
python -m src.cli demo "RRF 融合的 k 值默认是多少？"
```

> 说明：模型首次使用需已在本机 HuggingFace 缓存（`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`、`BAAI/bge-reranker-base`，embedding 对照另需 `BAAI/bge-small-zh-v1.5` 与 `moka-ai/m3e-small`）。全程 `HF_HUB_OFFLINE=1`，无外网请求。

## 四、主实验结论（2026-11-14）

四组对照，同语料、同分块、同嵌入、同 top-k=10，20 条标注 query（12 exact + 8 semantic），权威数据 `runs/20261114-final-bench/`：

| 类型 | 模式 | Recall@3 | Recall@5 | Recall@10 | MRR | nDCG | p50 时延 |
|---|---|---|---|---|---|---|---|
| exact | bm25 | 0.250 | 0.292 | **0.583** | 0.341 | 0.381 | **2.2ms** |
| exact | rrf | 0.542 | 0.708 | 0.708 | 0.639 | 0.575 | 32.6ms |
| exact | rrf_rerank | **0.667** | **0.792** | **0.875** | **0.729** | **0.721** | 442.3ms |
| exact | vector | 0.417 | 0.458 | 0.667 | 0.442 | 0.447 | 25.6ms |
| semantic | bm25 | 0.125 | 0.125 | 0.167 | **0.391** | 0.194 | **3.1ms** |
| semantic | rrf | **0.167** | **0.208** | 0.208 | 0.354 | 0.209 | 29.3ms |
| semantic | rrf_rerank | 0.125 | 0.250 | **0.292** | 0.341 | **0.237** | 452.4ms |
| semantic | vector | 0.083 | 0.125 | 0.250 | 0.231 | 0.174 | 28.9ms |
| all | bm25 | 0.200 | 0.225 | 0.417 | 0.361 | 0.306 | **2.5ms** |
| all | rrf | 0.392 | 0.508 | 0.508 | 0.525 | 0.428 | 30.3ms |
| all | rrf_rerank | **0.450** | **0.575** | **0.642** | **0.574** | **0.527** | 445.4ms |
| all | vector | 0.283 | 0.325 | 0.500 | 0.358 | 0.338 | 26.5ms |

### 算法结论（三条立得住的）

1. **双路融合全面优于单路，重排在融合之上再进一步。** all 口径 MRR：BM25 0.361 → RRF 0.525（+45%）→ 重排 0.574（+60%）；exact 口径 R@3：0.250 → 0.542 → 0.667。**重排买的是头部名次与 R@10**（exact R@10 0.875），代价是 p50 从 30ms 涨到 445ms（重排器占 93% 时延，是链路绝对瓶颈）。
2. **纯 BM25 的 gold 普遍藏在中后段，融合把头部提上来。** exact 口径 BM25 的 R@3 只有 0.250、R@10 却有 0.583——逐条看 q01 gold 排第 8、q07 第 9、q08 第 9，同一批 gold 在 RRF 下到了第 1~4 名（`runs/analysis_failures.md` 第三节）。all 口径 BM25 的 R@10（0.417）是四模式最低，"头差"与"尾差"同时存在。**"R@10 高"不等于体验好**：对话检索入口只展示前几条，@3/@5 与 MRR 才是体验指标。
3. **语义改写类没有全线哑火，但头部仍然弱，3/8 条全灭。** 8 条 semantic 中 5 条至少命中 1 个 gold（q17/q19 命中 2/3），最好的口径是重排 R@10 0.292；但 R@3 全部 ≤0.167，q13（离线向量库选型）、q16（用词失配召回不准）、q20（粗排之后怎么再提一档）三条在任何模式下零命中，全部死在**跨文档同主题分辨**——gold 与干扰块主题词高度重叠（Chroma vs Qdrant 都讲向量库、rerank 概念散在两份文档）。**语义改写的普遍水平由 embedding 决定**，第六组探针已实测（见 ⑥）：换 bge-small-zh 后 semantic R@10 抬 50%~70%、q20 被救回，但 q13/q16 三个模型下仍全灭——最难的分辨要靠查询侧改写或文档侧结构。

### 工程结论（六组探针，2026-11-14，见 `runs/20261114-final-probes/` 与 `runs/20261114-embed-probe/`）

**① 候选数（rrf_rerank）：有增益但不是主要杠杆**

| 候选 k | Recall@3 | Recall@5 | Recall@10 | MRR | nDCG | p50 时延 |
|---|---|---|---|---|---|---|
| 10 | 0.475 | 0.575 | 0.642 | **0.608** | 0.554 | 416.3ms |
| 20（默认） | 0.450 | 0.575 | 0.642 | 0.574 | 0.527 | 466.8ms |
| 50 | **0.517** | **0.667** | **0.700** | **0.610** | **0.567** | 484.2ms |

候选 20→50：R@10 +9%（0.642→0.700）、MRR +6%，p50 只 +4%——**增益有限但确实存在，且时延几乎不涨（粗排多召回便宜）**。真正的杠杆是重排器本身：k=10 时 R@10 已达 0.642。旧版"候选 20→50 收益 28%"是重排静默降级的污染数据，已作废。

**② RRF k 在本规模下不敏感**

k = 10 / 30 / 60 / 100 / 1000 时 R@10 恒为 0.508、R@3 恒为 0.392；MRR 在 k=10 时 0.558、其余 0.525（差 6%，属噪声）。候选总量只有 40 块、取前 10，k 从 10 拉到 1000 不足以改变前 10 名集合。**实证了「RRF k 是衰减速度不是准确率旋钮」的口径：默认 60 即可，无需调参。**

**③ BM25 阈值同不敏感**

min_ratio = 0 / 0.1 / 0.2 / 0.3 时 R@10 恒为 0.533、MRR 恒为 0.5625；BM25 平均候选数仅从 20.0 降到 19.1。该测试集上 BM25 命中块分数普遍较高，阈值过滤不掉有效块。**保留默认 0.15 作为防全零 query 噪声的兜底，无需精调。**

**④ 中文分词必须分词：jieba+领域词 ≈ 纯 jieba ≫ 单字**

| 分词方式 | exact BM25 R@10 | semantic BM25 R@10 | all BM25 R@10 | all RRF R@10 |
|---|---|---|---|---|
| jieba+领域词 | 0.583 | 0.167 | 0.417 | 0.533 |
| jieba | 0.583 | 0.167 | 0.417 | 0.533 |
| 单字 | 0.292 | 0.250 | 0.275 | 0.517 |

- 领域词表与纯 jieba 指标完全一致：**本测试集的专有名词（RRF/BM25/HyDE/HNSW/GraphRAG）jieba 默认词典已覆盖**，词表价值需在更冷门领域验证——不要想当然认为加词表一定有用。
- 单字切分把 exact R@10 腰斩（0.583→0.292）：BM25 退化为字频统计，IDF 失效；但 semantic 反而从 0.167 升到 0.250——**字粒度对词汇失配有弱抵抗**。RRF 下 all 口径只差 0.016（0.517 vs 0.533）：融合把单字崩掉的部分从向量路补了回来。中文检索单字切分仍不可用（精确场景扛不住）。

**⑤ 块大小 500 是当前最优点（300 太碎、800 太粗）**

| chunk size | 块数 | all vector R@10 | all rrf R@10 |
|---|---|---|---|
| 300 | 681 | 0.142 | 0.042 |
| 500 | 470 | 0.525 | 0.533 |
| 800 | 387 | 0.133 | 0.100 |

**500 字是明显最优点**：300 太碎（gold 块内容被切碎、边界块变多），800 太粗（单块主题混杂、稀释相关性），两者都崩，且**向量路同样受影响**（0.142/0.525/0.133）。旧版"切分粒度对向量路无影响、只伤 BM25 与融合路"是首轮索引污染的假象（三组都读到同一份脏索引，向量指标才完全一致）。

**⑥ 中文 embedding 对照：换嵌入抬语义 50%~70%，代价是精确串头部，最难的跨文档分辨仍救不回**

同一语料 470 块、同一 20 条测试集、同一 top-k=10；每个模型独立 collection（`corpus-embed-<tag>`，先 reset 再重建），BM25 索引与 bge-reranker-base 全程共用；只跑会随嵌入变化的三个模式（vector / rrf / rrf_rerank）。`bge-small-zh` 按官方口径给 query 加指令前缀（"为这个句子生成表示以用于检索相关文章："），文档侧不加；MiniLM 无此前缀，作为同会话基线，三个模式与主实验（表二）逐项一致。逐条全量数据：`runs/20261114-embed-probe/probe_embedding_per_query.json`（3 模型 × 3 模式 × 20 条）。

| 嵌入 | 模式 | exact R@10 | semantic R@10 | all R@10 | all MRR | p50 |
|---|---|---|---|---|---|---|
| MiniLM（基线） | vector | 0.667 | 0.250 | 0.500 | 0.358 | 25.7ms |
|  | rrf | 0.708 | 0.208 | 0.508 | 0.525 | 25.1ms |
|  | rrf_rerank | **0.875** | 0.292 | **0.642** | 0.574 | 460.0ms |
| bge-small-zh | vector | 0.667 | 0.375 | 0.550 | 0.523 | 14.2ms |
|  | rrf | 0.708 | 0.417 | 0.592 | 0.588 | 17.7ms |
|  | rrf_rerank | 0.750 | 0.417 | 0.617 | **0.610** | 460.4ms |
| m3e-small | vector | 0.292 | 0.375 | 0.325 | 0.318 | 13.4ms |
|  | rrf | 0.375 | 0.417 | 0.392 | 0.439 | 15.6ms |
|  | rrf_rerank | 0.667 | **0.458** | 0.583 | 0.574 | 445.7ms |

1. **中文专用 embedding 抬语义，代价是精确串的头部。** bge-small-zh 把 semantic R@10 从 0.250/0.208/0.292（vector/rrf/重排）提到 0.375/0.417/0.417（+50%~+70%）；但 rrf_rerank 的 exact R@10 从 0.875 掉到 0.750——逐条看是 q07/q09/q10 三条精确串在 bge 的向量候选池里丢 gold：精确问法含专名，bge 编码后的向量近邻与 BM25 候选融合后，喂给重排器的组合变了。**换中文 embedding 是拿 exact 头部换 semantic 大盘，不是白捡。**
2. **m3e-small 语义不弱、精确路全面偏弱。** semantic R@10 与 bge 同档（vector 0.375），重排后 0.458 是全部组合最高；但 exact 只有 0.292/0.375/0.667，vector 与 rrf 下 all R@10 被拖到 0.325/0.392（重排救回 0.583，仍低于 bge 的 0.617）。中文技术语料精确串密度高，m3e-small 不宜单用。
3. **q13/q16 换任何 embedding 都救不回。** 原「semantic 3/8 全灭」中 q20 被 bge/m3e 救回（0/3→2/3）、q19 提到 3/3，但 q13（离线向量库选型）与 q16（用词失配）在 3 模型 × 3 模式共 9 组下全部零命中：前 10 名被同主题邻居块占满，gold 与干扰块分差极小。**embedding 决定语义召回的普遍水平；最难的跨文档同主题分辨要靠查询侧改写（HyDE）或文档侧结构（Contextual Retrieval）。**
4. **重排器与嵌入并非同族最优。** bge 嵌入 + bge-reranker 的 exact 头部（0.750）反而不如 MiniLM 嵌入 + 同一个 bge-reranker（0.875）。重排质量取决于粗排候选池有没有把 gold 带进来，候选池覆盖才是决定因素。

**复现口径**：m3e-small 的 rrf 汇总在首跑（同进程重建后立即测）与重放（跨会话重载持久化索引）之间差 0.0167——恰为 1 条 query 的 top-10 边界翻转（q09/q17/q18 互换 1~2 块），与索引重建噪声口径一致；vector 路两次完全一致。汇总已按重放会话（全量逐条）重算覆写，保证 `probe_embedding.json` 与逐条出自同一次测量。三模型之间的差异（0.1~0.4）远大于噪声（±0.02），结论不受影响。
